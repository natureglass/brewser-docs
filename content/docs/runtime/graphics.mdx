## Canvas 2D

Fully supported, backed by Skia. Text, paths, images, compositing and
`toDataURL` all work as in a desktop browser.

## WebGL 1

WebGL isn't hand-reimplemented — it's a bridge from JavaScript straight to the
Switch's Tegra X1 GPU. Shaders and draws run on real silicon, JIT-compiled, so
the question isn't *"is it built?"* but *"how much of the WebGL API surface and
how many extensions are wired through?"*. The complete context / draw / state /
buffer / texture / shader API is present for **both** versions, and extensions
are **driver-probed** — a name is advertised only when the underlying GL driver
actually supports it, so `getSupportedExtensions()` and `getExtension()` are
consistent by construction and never over-promise.

WebGL 1 is the safest, most compatible target.

- Complete GLSL ES 1.00 pipeline; textures (2D + cube), mipmaps, framebuffers / renderbuffers, depth textures
- Driver-probed extensions: `ANGLE_instanced_arrays`, `OES_vertex_array_object`, `OES_element_index_uint`, `OES_standard_derivatives`, `OES_texture_float` / `half_float` (+ `_linear`), `WEBGL_depth_texture`, `WEBGL_draw_buffers`, `EXT_sRGB`, `EXT_blend_minmax`, anisotropic filtering, plus the full compressed-texture family (S3TC / DXT, ETC1 / ETC2, ASTC, BPTC, RGTC)
- Real-world proof: Unity WebGL 1 exports run, and generative / demoscene / full-screen-shader apps are a platform specialty
- Gaps: coverage is broad but not exhaustive — an exotic `getExtension()` can still return `null`

## WebGL 2

Supported including advanced usage, and under active conformance hardening.

- Full GLSL ES 3.00 (`#version 300 es`) surface: VAOs, uniform buffer objects, transform feedback, 3D & 2D-array textures (`texImage3D` / `texStorage3D` / `framebufferTextureLayer`), sampler objects, sync / fence objects, occlusion & timer queries, integer vertex attributes, and every `uniform*` / `uniformMatrix*` variant
- Multiple render targets, `blitFramebuffer`, multisample renderbuffers, `readBuffer` / `drawBuffers`, `EXT_color_buffer_float` / `half_float`, `EXT_texture_norm16`, sRGB
- Real-world proof: complex Three.js (r162) scenes, PMREM environment maps and multi-pass post-processing render JIT-optimized on hardware
- Gaps: layered / 3D-texture *sampling* (`sampler3D` / `sampler2DArray`) is limited by the Tegra GPU driver rather than the bridge; conformance is still being hardened — if you hit a missing method or extension, **please report it**

Coverage here is broad but not exhaustive. For the headline coverage numbers,
see [Engine Status](/docs/engine-status).

## Shader tips

GLSL fragment/vertex shaders work well and are a great fit for the platform —
generative art, demoscene-style effects and full-screen shader apps are a
Brewser specialty.

## Performance notes

The Tegra X1 is capable but not a desktop GPU:

- Prefer flat fills over gradients and shadows in UI-heavy apps.
- Batch draw calls; avoid per-frame shader recompilation.
- Target 720p (docked output is scaled).

See [Hints & Tips → Performance](/docs/tips/performance) for more.
